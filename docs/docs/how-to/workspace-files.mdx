The [workspace](/concepts#workspace) is a git folder of Markdown — knowledge and plans, all just files. The knowledge itself follows an open standard ([OKF](#the-knowledge-graph-is-an-okf-bundle), below). Every workspace route derives your identity from the API key; you never pass a subject.

You can have **many workspaces** — your Personal one, ones you created, ones shared with you — all equal-rank. The **active set** (the ones you have switched on) decides what agents mount and what the client shows; reads are addressed by each workspace's `slug`.

## Browse and read

```bash
# your ACTIVE SET — the workspaces currently switched on, in mount order
curl -H "X-API-Key: $API_KEY" "$API_BASE/agent/workspace/active"
# → { "subject": "...", "active": [ { "slug": "...", "role": "...", "write": true, ... } ] }

# a workspace's file tree (slug from the active set; omitting slug is a deprecated
# legacy form — always address a workspace explicitly)
curl -H "X-API-Key: $API_KEY" "$API_BASE/agent/workspace/tree?slug=<slug>"
# → { "files": ["kg/entities/acme.md", "meetings/2026-06-29-acme.md", ...] }

# one file's content (404 if absent)
curl -H "X-API-Key: $API_KEY" "$API_BASE/agent/workspace/file?path=kg/entities/acme.md&slug=<slug>"
# → { "path": "...", "content": "..." }

# git state — branch, uncommitted changes, recent commits
curl -H "X-API-Key: $API_KEY" "$API_BASE/agent/workspace/git?slug=<slug>"
```

Pass `hidden=true` to `tree` to include dotfiles. `git` is the durable state and the undo — every agent write is a commit.

## The knowledge graph is an OKF bundle

The `kg/` subtree follows the [Open Knowledge Format](https://github.com/GoogleCloudPlatform/knowledge-catalog/tree/main/okf) (OKF) v0.1 — Google's open, vendor-neutral standard for markdown knowledge. Each entity is one file at `kg/entities/<type>/<slug>.md` with YAML frontmatter:

```markdown
---
type: company            # OKF's only required key
id: acme-corp            # Vexum-required: stable slug, unique per type
title: Acme Corp         # Vexum-required: human title
description: Design-partner prospect, met at OSFF.   # OKF recommended
resource: https://acme.example.com                   # OKF recommended
tags: [prospect]
timestamp: 2026-07-02T14:00:00Z
---

Body is plain markdown. Entities cross-reference each other with [[wikilinks]]
by title — the knowledge graph emerges from the links.
```

Vexum's frontmatter contract (`type`/`id`/`title` required, per the [`workspace.v1` schema](https://github.com/Vexa-ai/vexa-core/blob/main/core/agent/contracts/workspace.v1/workspace.schema.json)) is a strict superset of OKF, which requires only `type` — so every workspace is a conformant bundle any OKF consumer can read, and `[[wikilinks]]` are a tolerated extension.

Two **reserved filenames** carry no frontmatter and are not entities:

- `index.md` — a per-directory listing (`- [Title](file.md) — description`) for progressive disclosure; seeded workspaces ship them generated, and the agent maintains them as entities are added or removed.
- `log.md` — optional change history, newest first, grouped under `## YYYY-MM-DD` headings.

Because the bundle is just files in git, it is portable by construction: `tree` \+ `file` above read it over the API, and a `git clone` (or the swap endpoint below) moves the whole knowledge base between tools — nothing about it is Vexum-specific.

## Upload documents

Add files to the workspace so agents can ground on them (multipart; ≤25 MB each):

```bash
curl -X POST "$API_BASE/agent/workspace/upload" \
  -H "X-API-Key: $API_KEY" \
  -F "files=@./contract.pdf" -F "files=@./notes.md"
# → { "files": [ { "name": "contract.pdf", "path": "..." }, ... ] }
```

## Initialize a fresh workspace

Idempotent — seeds the workspace if it doesn't exist yet:

```bash
curl -X POST "$API_BASE/agent/workspace/init" -H "X-API-Key: $API_KEY"
# → 201 { "workspace": "...", "seeded": true, "already_initialized": false }
```

## Multiple workspaces — activate, attach, share

Workspaces are **flat and equal-rank** — Personal included. Activation is **additive**: switching a workspace on mounts it _alongside_ the others, switching it off removes its files from the client and the agent's next turn. The first active workspace is the agent's working directory.

A workspace can be **shared**: mint an invite, the other person accepts, and it appears in their workspace list with a per-member role — their agents mount it alongside their own workspaces, and each member's writes commit under their own identity. In the terminal, the workspace **manage panel** covers members, invites, GitHub push/pull, and the workspace's purpose. Private chat history never rides along — conversations live in each member's private `_system` tier, not in the workspace.

### Attach your own git repo

Swap in an external git repo as a workspace — the current one is **parked**, not lost:

```bash
curl -X POST "$API_BASE/agent/workspace/swap" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"repo":"https://github.com/acme/knowledge.git","ref":"main","token":"<git-token>"}'
```

Omit `repo` to swap back to the seed workspace. Check what's attached:

```bash
curl -H "X-API-Key: $API_KEY" "$API_BASE/agent/workspace/attached"
# → { "active": {...}, "parked": [...] }
```
